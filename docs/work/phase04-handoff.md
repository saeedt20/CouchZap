# تحویل مرحلهٔ چهارم CouchZap

تاریخ: ۱۴ اکتبر ۲۰۲۶ · شاخهٔ محلی: `codex/phase04-polish-validation`

این مرحله روی سه مرحلهٔ قبلی اجرا شد. مبنای ورود مرحلهٔ چهارم commit `267b99c` است؛ گزارش‌های [مرحلهٔ ۱](phase01-handoff.md)، [مرحلهٔ ۲](phase02-handoff.md) و [مرحلهٔ ۳](phase03-handoff.md) سابقهٔ تغییرات و آزمون‌های آن‌ها را ثبت می‌کنند.

## تغییرات رابط

- عرض پنل فهرست و تنظیمات در TV مشترک و برابر 420dp شد؛ اتصال هر دو پنل به لبهٔ چپ و محتوای RTL فارسی حفظ شده است. در گوشی عمودی، عرض آن‌ها تمام صفحه است.
- حاشیهٔ محتوای TV حداقل 24dp یا ۵ درصد ابعاد صفحه است. Info نیز حاشیهٔ امن ۵ درصد و عرض حداکثر 420dp دارد.
- کادر دائمی دور ردیف‌های معمولی حذف شد؛ فوکوس روشن و واضح، و انتخاب با sage تیره‌تر حفظ شده‌اند. تغییر فوکوس اندازهٔ ردیف را عوض نمی‌کند؛ پاسخ فوکوس فوری باقی مانده است.
- header فشرده‌تر، ردیف‌های فهرست 56dp با فاصلهٔ 4dp و نام 18sp هستند. حداقل هدف لمس کنترل‌ها 48dp حفظ شده است. زیرصفحه‌های تنظیمات از همان ظاهر آرام ردیف استفاده می‌کنند.
- در Info، نام و لوگو در ردیف اصلی‌اند؛ ساعت و شماره در ردیف ثانویه قرار گرفته‌اند. برچسب‌های کوچک به 15sp افزایش یافته‌اند. نام لاتین در رابط فارسی کنار لوگو راست‌چین است، بدون تغییر ترتیب حروف.
- وضعیت اتصال، buffering، پخش و خطا همچنان از وضعیت واقعی player می‌آید. دادهٔ EPG ساختگی وارد برنامه نشده است.

## حرکت و چرخهٔ عمر

- ورود welcome فقط یک بار اجرا می‌شود: زمان نهایی 620ms، فاصلهٔ ورود متن/اقدامات 60ms، alpha و جابه‌جایی عمودی 10dp، با درخشش کوتاه صاعقهٔ لوگوی موجود.
- ورودی از ابتدا فعال است. اولین ACTION_DOWN ریموت یا لمس، intro را تمام می‌کند و همان رویداد به مسیر عادی ورودی می‌رود. فوکوس منتظر پایان افکت نمی‌ماند.
- روی API 24/25، پنل‌ها همان مسیر فوریِ محافظت‌شده را دارند؛ روی API 26 به بالا، ورود پنل fade و translation کوتاه 10dp/150ms است. بستن پنل فوری است.
- شناسهٔ نسل برای پایان animation و reset صریح alpha/translation/visibility، از اثر callback قدیمی هنگام باز/بسته شدن سریع جلوگیری می‌کند. startDelay نیز reset می‌شود؛ لایهٔ سخت‌افزاری دائمی یا blur اضافه نشده است.
- Back، بازگشت زیرصفحه، تغییر زبان، تغییر configuration، توقف و destroy حالت نهایی را تثبیت می‌کنند. Viewهای جداشدهٔ تنظیمات نیز قبل از جداسازی animation خود را تمام می‌کنند.
- خاموش بودن animation سیستم رعایت می‌شود. سوییچ اضافی Reduce motion یا فونت جدید اضافه نشده است؛ فونت native و سازگاری Android 7 حفظ شده‌اند.
- علاقه‌مندی در Info یک واکنش alpha کوتاه 140ms دارد. shutter پخش، گذار کوتاه موجود را با لغو امن انجام می‌دهد؛ برای صدای CRT یا افکت، تأخیر جدیدی به zap اضافه نشده است.

## صدای CRT

کنترل «صدای جابه‌جایی شبکه» داخل **تنظیمات ← پخش** است و انتخاب ذخیره می‌شود. **خاموش بودن پیش‌فرض و پیش‌نمایش هنگام فعال‌کردن، انتخاب اجرایی پیشنهادی این candidate است؛ تصمیم صریح کاربر دربارهٔ پیش‌فرض ثبت نشده است.**

فایل صوتی original از [generator](../../tools/generate_crt_sound.py) تولید شده و recording یا sample شخص ثالث ندارد. [شرح و مجوز CC0](../assets/crt_sound.md) همراه سورس است.

| مشخصهٔ اندازه‌گیری‌شده | مقدار |
| --- | --- |
| طول | 160ms |
| فرمت | PCM16، mono، 22050Hz |
| اندازهٔ WAV | 7100 bytes |
| peak فایل | حدود ‎−14.9dBFS |
| RMS فایل | حدود ‎−32.6dBFS |
| gain پخش | 0.35؛ peak دیجیتال پس از gain حدود ‎−24dBFS |

قله clipping ندارد و ابتدا/انتهای نمونه صفر و fade کوتاه دارند. **این اندازه‌ها تضمین بلندی ادراکی روی TV نیستند؛ شنیدن و تنظیم روی دستگاه واقعی باقی است.**

- hook صوتی فقط در commit جابه‌جایی به هویت کانال متفاوت است. شروع اولیه، refresh همان کانال، مرور ردیف‌ها، retry و reconnect صدا نمی‌سازند.
- debounce موجودِ نگه‌داشتن CH+/CH−، یک صدا برای انتخاب نهایی می‌دهد. SoundPool حداکثر یک stream دارد و قبل از پخش جدید، قبلی متوقف می‌شود.
- صدای MEDIA، mute/volume صفر و حالت silent دستگاه رعایت می‌شوند؛ حجم سیستم یا صدای برنامه افزایش نمی‌یابد.
- آماده‌سازی و decoding محلی روی worker هستند. failure آماده‌سازی قابل تکرار است و optional audio برنامه را crash نمی‌کند. completion بعد از خاموش‌کردن، pause یا destroy پیش‌نمایش عقب‌افتاده تولید نمی‌کند؛ منابع هنگام خروج آزاد می‌شوند.

## آزمون و محدودیت‌ها

| بررسی | نتیجه |
| --- | --- |
| `testDebugUnitTest` | ۸۹ تست؛ صفر شکست، صفر error و صفر skipped |

| رگرسیون مراحل قبل | در مجموعهٔ کامل موفق؛ شامل فهرست طولانی، خطای async، Back/فوکوس، منابع و حفظ داده |
| native screenshots | رندر و بررسی چیدمان موفق روی API 28 |
| `lintDebug` | صفر خطا، ۱۲۴ هشدار؛ lint بدون هشدار نیست |
| `assembleDebug` | موفق |
| `compileDebugAndroidTestKotlin` | موفق؛ اجرای instrumentation روی دستگاه انجام نشده است |
| `git diff --check` | موفق |

۱۷ case بیشتر از تحویل مرحلهٔ سوم اجرا شده‌اند: ۱۶ اجرای تست‌های جدید روی دو API و یک case رندر چهار نما در دو زبان. یک assertion اولیهٔ رندر، عرض اندازه‌گیری‌نشدهٔ پنل GONE را با پنل باز مقایسه می‌کرد؛ با مقایسهٔ layoutParams و سپس عرض واقعی پنل باز اصلاح شد. نتیجهٔ نهایی هیچ تست شکست‌خورده‌ای ندارد.

هیچ دستگاه adb، شبیه‌ساز قابل اجرا یا باکس/گوشی واقعی به این محیط متصل نبود. **Robolectric شبیه‌ساز Android یا آزمون GPU/decoder نیست.** نتیجهٔ API 24 به معنی تأیید باکس XDSR685 HDR نیست. Android 16 نیز اینجا اجرا نشده است. زمان شروع واقعی و frame timing روی سخت‌افزار اندازه‌گیری نشده‌اند؛ ادعای «بدون لگ روی باکس» نداریم.

آزمون‌های باقی‌مانده روی دستگاه: نصب روی نسخهٔ موجود بدون حذف داده، پخش stream واقعی و TLS سیستم، نگه‌داشتن ریموت با خطای شبکه، باز/بسته شدن سریع پنل‌ها، Home/بازگشت و خاموش‌روشن، حس بلندی صدا در mute و حجم‌های مختلف، و زبان فارسی روی Android 7 و Android 16.

## APK candidate

طبق درخواست قبلی کاربر برای ساخت APK در پایان مرحلهٔ چهارم، فایل محلی امضاشدهٔ شامل هر چهار مرحله ساخته شد. این درخواست بر محدودیت ساخت APK در سند برنامه تقدم دارد؛ مجوز انتشار GitHub یا افزایش نسخه نیست.

نام بسته `com.couchzap.iptv`، نسخهٔ `2.0.2`، versionCode `8`، minSdk `24` و targetSdk `35` ثابت‌اند. TLS، pinned certificate آپدیت و قواعد اعتبارسنجی updater تغییر نکرده‌اند. این candidate هم‌نسخه است و updater خودکار آن را به‌عنوان نسخهٔ بالاتر پیشنهاد نمی‌کند؛ نصب فایل محلی برای آزمون لازم است.

- `assembleRelease` با R8 و resource shrinking موفق شد؛ `lintRelease` صفر خطا و ۱۲۴ هشدار دارد.
- فایل: **CouchZap-stage4.apk**؛ اندازهٔ دقیق **2,723,396 bytes** (حدود 2.60MiB).
- `apksigner verify --verbose --print-certs` موفق است؛ APK Signature Scheme v2 معتبر و سازگار با minSdk 24 است. certificate SHA-256 با مقدار pinned updater و امضای release قبلی برابر است:
  `539f14a4b71cc830108cffefa8778ec06797be539c90ab80bc0c89b0c60eb187`
- SHA-256 فایل:
  `2fd9f3e3ed05f491e7462fe607425a1cd181261bd9119f617a9926485379a3bb`
- `aapt2 dump badging` نام بسته، نسخه، min/target SDK و launcher معمولی/Leanback را تأیید کرد.
- این فایل یک **candidate محلی امضاشده برای نصب و آزمون** است؛ release عمومی جدید نیست. سازگاری امضا تأیید شده، اما نصب واقعی روی نسخهٔ موجود در این محیط آزمون نشده است.

انتشار release، push به GitHub و تغییر شمارهٔ نسخه انجام نشده‌اند. سورس، گزارش و تصاویر در شاخهٔ محلی مرحلهٔ چهارم ثبت می‌شوند؛ کلید خصوصی و رمزها در مخزن یا گزارش قرار ندارند.
